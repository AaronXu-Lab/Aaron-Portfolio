# Prompt 擂台 作品接入指南

本指南供在 Aaron-Portfolio 项目中启动的新 AI 会话使用。创作题目以用户提供的 Prompt 为准；本文件只规定交付与验证方式，不限定艺术风格或实现技术。先阅读项目 `AGENTS.md`。

## 独立实现

请独立完成作品，不读取、搜索或参考 `public/tools/prompt-lab/entries/` 下其他作品的源码与素材，也不要通过浏览器预览、截图或历史版本参考其他作品。禁止复制或复用其他作品的实现。

接入时可读取项目 `AGENTS.md`、本指南、展示台 `README.md` 与 `entries.json`，用于了解约定和避免 ID 重复；可检查拟用目录是否存在，但不要遍历其他作品的内容。代码搜索应限定在自己的作品目录或必要的公共基础设施中，排除其他作品目录。通用第三方库及其官方文档可以使用。

这是一项执行约束，不是文件访问权限隔离。若意外读到其他作品内容，应如实说明，不将此次结果描述为完全独立实现。

## 交付位置

1. 在 `public/tools/prompt-lab/entries/<作品ID>/` 新建独立目录，入口为 `index.html`。作品 ID 使用英文小写、数字和连字符，包含模型名与运行编号，例如 `model-name-pelican-run-01`。先核对登记表并检查拟用目录是否存在，确保唯一，不覆盖以前的运行。
2. 将代码、依赖和素材保存在自己的作品目录内，使用相对路径。允许使用本地打包的 3D 库，不依赖运行时外部 API、CDN 或在线字体。
3. 作品在展示台 iframe 中运行，不访问或修改父页面。如需本地存储，使用包含作品 ID 的独立键名前缀。
4. 只新增自己的作品，并向下述登记表追加记录。不要修改展示台、固定 Prompt、既有记录或其他模型的作品。

## 登记作品

向 `public/tools/prompt-lab/entries.json` 数组末尾追加一条记录，保持有效 JSON：

```json
{
  "id": "model-name-pelican-run-01",
  "model": "实际模型名称",
  "version": "未提供",
  "reasoningEffort": "未提供",
  "title": "作品名称",
  "date": "YYYY-MM-DD",
  "promptVersion": "pelican-v1",
  "entry": "entries/model-name-pelican-run-01/index.html"
}
```

示例值必须替换：`id` 与目录名一致，`entry` 相对于 `public/tools/prompt-lab/`；`model` 与 `version` 如实填写，无法确认时写「未提供」，不要猜测；`date` 使用本次实际测试日期。当前「鹈鹕骑自行车」固定题目版本为 `pelican-v1`。

### 模型名称与思考强度

下拉菜单统一显示 `{model} · {reasoningEffort}`，例如 `GPT-6.1 Sol · High`。

- `model`：完整的模型显示名，包含型号与系列，例如 `GPT-6.1 Sol`。不要将思考强度写进模型名。
- `reasoningEffort`：本次会话实际配置的思考强度，必填。英文档位统一使用 `None`、`Minimal`、`Low`、`Medium`、`High`、`XHigh`、`Max` 或 `Ultra`；其他模型的档位保留其正式名称。只能依据明确的会话配置或用户提供的信息填写，不能根据题目难度或自己的表现推测。未知写「未提供」，明确不支持此设置时写「不适用」。
- `version`：保留用于记录准确版本或快照，不再用于下拉菜单的第二部分。
- 同一模型以不同思考强度运行时，新建作品 ID 和记录，不能覆盖此前结果。

以上 `GPT-6.1 Sol · High` 仅是格式示例，不代表当前会话的实际配置。既有记录缺少 `reasoningEffort` 时，界面显示「未提供」，不伪造模型或思考强度。

登记后，展示台自动将作品加入下拉菜单，无需修改页面代码。

## 验证与交付

- 执行 `npm run build`，构建必须零错误。
- 使用 `npm run preview`，打开 `/tools/prompt-lab/?model=<作品ID>`，验证下拉菜单能选中自己的作品及其主要交互，不打开其他作品进行参考。Astro dev 不返回这些静态目录的默认首页。
- 检查 320px、390px、430px 宽度下的触控布局、横向溢出和动画；如实说明浏览器模拟与真机验证的范围。
- 作品拆分为多个资源时，先联网完整使用一次，再检查离线加载。展示台自动缓存已请求的本地资源，无需修改 service worker。
- 若使用 Playwright，结束时关闭为本次验证创建的命名会话。
- 最终提供作品 ID、预览地址、验证结果及未验证项。不执行 Git 提交、推送或部署，除非用户另外明确要求。
